The Google Workspace System

How the System is Built

Everything runs in Google Sheets, Google Forms, and Google Docs. Admin-only access. Volunteers receive printed pick sheets only. No external tools, no technical maintenance required.

📋 The Process Steps
⚙️ System & Data Details
📦
Step 01

Stock Intake

When a donation arrives, stock is counted by category and logged into the system. This is the only point at which physical stock levels rise.

1

Count & Categorise

Sort items into the standard categories matching the Goods Out Master. Count quantities per category.

2

Record Delivery

Admin opens the Delivery Log (Tab 5). Enters donor name, date received, total donation weight, and quantity per item category.

3

Stock Rises

Once a received date is confirmed (today or earlier), physical stock levels in the Stock Ledger (Tab 4) update automatically.

✅

Stock Ledger Updated

Current physical stock is now accurate. The Dashboard and Forecast reflect the new levels immediately.

📋 Delivery Log — Tab 5
Each donation creates multiple rows — one per item category — all sharing the same delivery reference.
Delivery Reference · Donor Name · Expected Date · Received Date · Total Donation Weight · Item Category · Quantity
If Received Date is blank or future → feeds Forecast only. If Received Date is today or earlier → adds to physical stock.
📊 Future Deliveries
Expected donations are entered in the same Delivery Log with an expected date only. They appear in the 2-month forecast but not in current stock until confirmed received.
⬇️ Stock is now live in the system — ready for planning
👤
Step 02

Beneficiary Registration

Following the referral and onboarding process, admin creates the beneficiary's record in the system. This is the starting point for all planning and picking.

1

Create Record

Admin enters the beneficiary into Tab 1 (Beneficiary Database). A unique reference number is auto-generated.

2

Household Details

Total adults, number male/female, children with birth month/year, dietary requirements and any notes.

3

Logistics Flags

Group 1 or 2 (which half of the month), Collection or Delivery (C/D), PR or DR referral type, collection frequency.

4

Support Period

Support start and end dates entered. Status set to Active. Record is now visible across the system.

🆔

Beneficiary Record Live

Unique reference number created. Record feeds the pick plan, to-do list, and dashboard. No address or contact details stored here — those remain in the referral system.

📋 Tab 1 — Beneficiary Database
Reference Number · First Name · Total Household · Adults · Male · Female · Children (with DOB) · Dietary Requirements · Notes · Group (1/2) · C/D · PR/DR · Frequency · Start Date · End Date · Status
First name and household composition only. Full contact details held exclusively in the referral system.
Group 1/2: Which half of the month they collect.
C/D: Collection from foodbank or Delivery to them.
PR/DR: Professional or Direct Referral (reporting only).
⬇️ Beneficiary registered — time to build their plan
🗓️
Step 03

Building the Pick Plan

Admin creates the full support plan for the beneficiary — all scheduled picks for their support period. A template auto-populates quantities based on household size and composition, which admin can then adjust.

1

Open Plan Form

Admin opens the plan entry view in Tab 2. The form layout mirrors the Goods Out Master — categories grouped identically.

2

Select Template

Admin selects the base template from a dropdown. Quantities auto-populate based on the beneficiary's household size, adult/child split pulled from Tab 1.

3

Review & Adjust

Admin reviews all quantities and adjusts as needed for dietary requirements, preferences, or stock availability. Free-from items toggled separately.

4

Set Pick Dates

Admin sets all scheduled pick dates for the support period. Each date becomes a separate row in Tab 2. A unique Pick Code is generated per pick (e.g. MAR25-001).

📋

Plan Committed — Stock Reserved

All scheduled picks now appear in the system. Stock is shown as Committed on the dashboard and forecast — but is NOT yet deducted from physical stock. Nothing leaves the ledger until a pick is confirmed complete.

📋 Tab 2 — Pick Plan
One row per scheduled pick. A beneficiary on a 3-month monthly plan has 3 rows. A fortnightly beneficiary has more. Each row is one pick event.
Month + Year + Sequential Number. e.g. MAR25-001, MAR25-002. Resets each month. Printed prominently on the pick sheet.
If a beneficiary's household size or needs change, admin edits their rows directly in Tab 2. The plan is always the live source of truth.
⚙️ Tab 9 — Template Config
One row per item category. Rules define standard quantities based on total household size and adult/child split. Admin adjusts rules here — changes apply to all new plans automatically.
⬇️ Plan live — picks visible in the 2-week to-do list
✅
Step 04

The 2-Week To-Do List

Admin's daily operational view. Shows all picks due in the next 14 days, organised by day, split by Collection and Delivery. No need to scroll through the full database — everything needed is visible at a glance.

1

Today's Picks

Each day shows as a clear section. Collections and Deliveries shown separately. Each pick shows beneficiary name and pick code only — low cognitive load.

2

Status at a Glance

Planned picks show normally. Completed picks are greyed out or struck through. Admin can instantly see what still needs preparing.

3

Generate Pick Sheet

Next to each pick is a button. Admin clicks it — a print-ready Google Doc is generated for that single pick. No need to open Tab 2.

🖨️

Pick Sheet Printed

A clean, accessible printed sheet is handed to the packer. Large font, clear checkboxes, low visual noise. The pick code is printed prominently top and bottom.

🖨️ The Printed Pick Sheet
Support Date · Month · Support From/To · Group (1/2) · C/D · PR/DR · Beneficiary Name · Dietary Requirements & Notes · No. of Children & Ages · No. of Adults · M/F Split · Total Household · Pick Code
Only items with a planned quantity appear. Each item has a large checkbox and clearly stated quantity. Categories grouped as per Goods Out Master. Items not in this pick are invisible.
Packed By (initials) · Checked By (initials) · Notes · Pick Code (repeated)
⚙️ Tab 3 — To-Do List
Pulls from Tab 2. Shows next 14 days only. Groups by day. Separates Collections from Deliveries within each day. Updates automatically as plans are added or picks completed.
⬇️ Volunteer packs the parcel using the printed sheet
📝
Step 05

Post-Pick Check-In

After packing, admin records what actually went out using the post-pick form. This is the moment stock is deducted. The form is mobile-friendly — admin can complete it on phone or tablet, same day or up to a few days later.

1

Enter Pick Code

Admin opens the Google Form and types the pick code from the printed sheet. The form retrieves the planned quantities for that pick.

2

Confirm Actuals

For each item, admin confirms what actually went out. Blank = as planned. Zero = not distributed. Different number = change. Extra items can be added here too.

3

Log Initials

Admin records who packed and who checked the parcel. Notes field for anything unusual or items substituted.

4

Mark Complete

Admin taps the Mark as Complete button. This submits the form and triggers all downstream updates simultaneously.

📉

Stock Deducted — Pick Closed

Actual quantities overwrite planned quantities in Tab 2. Status updates to Complete. Physical stock deducts from Tab 4. Pick disappears from the to-do list. Dashboard and forecast update instantly.

📱 Google Form — Post-Pick
Mobile, tablet, or desktop. Admin-only link. Designed for quick completion after packing.
Stock is ONLY deducted when the Mark as Complete button is pressed. Planning picks in advance commits stock to the forecast but does not reduce physical stock levels.
Any item added beyond the plan (e.g. fresh produce) is recorded and also deducted from stock. Nothing leaves the warehouse without being counted.
⚙️ Tab 8 — Post-Pick Audit Log
Every form submission is preserved in raw form in Tab 8. Planned vs actual quantities visible for every pick ever completed. Used for reporting and dispute resolution.
⬇️ Pick complete — stock ledger and dashboard updated
📊
Step 06

Stock Control & Forecasting

The system maintains three views of stock at all times — what's physically on the shelf, what's committed to upcoming planned picks, and what's forecast to remain after all planned picks go ahead. The 2-month weekly forecast helps admin plan donation requests proactively.

1

Current Stock

Physical items confirmed on the shelf. Rises when deliveries are confirmed. Falls when picks are marked complete.

2

Committed Stock

Reserved for planned but not yet completed picks. Visible so admin knows what's already spoken for, even though it hasn't left the shelf yet.

3

Forecasted Stock

Current minus committed, plus expected future deliveries. Projects where stock will be if all plans go ahead as scheduled.

4

2-Month Forecast

Week-by-week breakdown per item category for the next 8 weeks. RAG indicator flags any week where forecasted stock drops below minimum threshold.

🚦

Early Warning System

Admin can see weeks in advance when specific items will run low — enabling proactive donation requests before stock runs out, not after.

📋 Tab 4 — Stock Ledger
Matches Goods Out Master categories exactly. Columns: Item · Min Threshold · Current Stock · Committed · Forecasted · RAG Status
🔴 Below Minimum 🟡 Within 20% 🟢 Healthy
📈 Tab 6 — Weekly Forecast
Per item, per week: Opening Stock → Planned Picks Out → Expected Deliveries In → Forecasted Closing Stock. Any week below threshold is highlighted red automatically.
⬇️ All data flows into the Admin Dashboard
🖥️
Step 07

Admin Dashboard

A single-screen management view. Everything an admin needs to understand the health of the foodbank at a glance — beneficiary numbers, upcoming picks, stock status, and forecast alerts. No navigation required.

1

Beneficiary Summary

Total active beneficiaries. Breakdown by Group 1/2 and Collection vs Delivery. Picks this week and this month.

2

Pending Check-Ins

Picks marked as complete on the physical sheet but not yet submitted via the post-pick form. Admin can see at a glance what's outstanding.

3

Stock Health Table

All items with current, committed, and forecasted stock. Items below minimum threshold surfaced at the top of the list, highlighted red.

4

Forecast Alerts

Any week in the next 8 weeks where any item is forecast to drop below minimum is flagged prominently. Enables proactive donor outreach.

👁️

Total Operational Visibility

Admin always knows the state of the foodbank — current, committed, and future. Decisions about donor requests, capacity, and planning are data-driven rather than guesswork.

⚙️ Tab 7 — Dashboard
All figures update automatically via formulas. No manual input required. Admin opens Tab 7 and the current state of the foodbank is instantly visible.
Active Beneficiaries · Picks This Week · Picks This Month · Awaiting Check-In · Items Below Threshold · Forecast Shortfall Weeks
⚠️ Low Stock Protocol
Set per item in Tab 4. When current or forecasted stock drops below threshold, item appears red on Dashboard. Admin sees this immediately on opening the system.
Admin contacts donors proactively. Anticipated delivery entered into Delivery Log as Expected, immediately improving the forecast view.
⬇️ Cycle repeats — every pick, every donation, every week
Step 08

Plan B — Resilience

The system is built on Google Workspace — widely available and reliable. But operational continuity must be guaranteed even if digital tools are unavailable on a pick day.

1

Pre-Print Sheets

Admin can generate and print all pick sheets for the week in advance. If the system is down on pick day, printed sheets are already in hand.

2

Manual Check-In

Post-pick forms can be completed later when the system is back online. Pick code on the sheet ensures the record can always be reconciled.

3

Laminated Backup

A set of laminated category cards can be maintained for emergency use, with pick codes and names written in dry-wipe marker.

💪

Service Never Stops

The community is served regardless of technology availability. The digital system catches up when it's back online — no data is lost.

🔁 Data Integrity
When back online, admin submits any outstanding post-pick forms using the pick codes from printed sheets. The audit log in Tab 8 preserves the date of submission, so late entries are clearly identifiable.
