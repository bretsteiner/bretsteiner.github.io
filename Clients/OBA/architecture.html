Setup Guide
Deploy From Scratch
⚠️
Prerequisites: A Google account with access to Google Cloud Console, an existing OBA Operations Google Sheet (or a copy of it), and somewhere to host a static HTML file (GitHub Pages, Netlify, etc.).
☁️
Step 1 — Google Cloud Project
console.cloud.google.com
1
Create a new project
Go to console.cloud.google.com → New Project. Name it something like "OBA Plan Creator".
2
Enable required APIs
APIs & Services → Library. Search for and enable: Google Sheets API Google Identity Services (automatic via GIS script)
3
Create an API Key
APIs & Services → Credentials → Create Credentials → API Key. Restrict it to the Sheets API and your hostname. Copy the key.
4
Configure OAuth consent screen
APIs & Services → OAuth consent screen. Set type to Internal (for organisation use) or External. Add your hosting domain under Authorised domains.
5
Create an OAuth 2.0 Client ID
Credentials → Create Credentials → OAuth client ID. Type: Web application. Add your hosted URL to Authorised JavaScript origins: # Example origins https://yourorg.github.io https://your-app.netlify.app http://localhost:5500 # for local dev
📄
Step 2 — Configure the HTML File
3 constants to set
1
Open the HTML file in a text editor
Find the configuration block near the top of the <script> tag (around line 1195).
2
Set the three constants
// ← Your Google Sheet's ID // (from the URL: /spreadsheets/d/THIS_PART/edit) const SHEET_ID = "your-sheet-id-here"; // ← API key from Cloud Console const API_KEY = "AIzaSy..."; // ← OAuth Client ID from Cloud Console const CLIENT_ID = "123456-abc.apps.googleusercontent.com";
3
Verify tab names match
The sheet tab names in your spreadsheet must exactly match these constants (or update them to match): const PICK_TAB = "2. Pick Plan"; const BEN_TAB = "1. Beneficiary Database"; const LEDGER_TAB = "4. Stock Ledger"; const CONFIG_TAB = "5a. Item Config"; const REF_TAB = "10. Reference Data";
4
Share the Google Sheet
The sheet must be shared with (or owned by) the Google accounts that will use the tool. Set permission to Viewer minimum — the OAuth token will grant write access via the API scope.
🚀
Step 3 — Host the File
One file to deploy
1
Choose a static host (see options below)
Since this is a single HTML file with no build step, any static host works. GitHub Pages is the simplest free option for a non-technical team.
2
Upload / commit the HTML file
For GitHub Pages: create a repo, commit the file as index.html, enable Pages from Settings → Pages → main branch.
3
Add origin to OAuth client
Return to Google Cloud Console → Credentials → your OAuth client → add the live URL (e.g. https://yourorg.github.io) to Authorised JavaScript Origins. Save.
4
Test sign-in
Open the live URL in a browser. The Google sign-in popup should appear. Sign in with an account that has access to the sheet. Picks should load on the home screen.
📋
Step 4 — Spreadsheet Setup
Structure required
1
Ensure header rows exist in each tab
The app skips the first 3 rows of Tab 1 and Tab 2 (title, note, header). Row 4 onwards is treated as data. The Pick Plan tab needs column headers in row 3 matching the PC constants.
2
Stock Ledger — item row format
Col A = Item Name, B = Item Code (e.g. BRK-001), C = Portion Size, D = Section Colour (hex), E = Section Name. Section header rows have a name in col A but no code in col B.
3
Reference Data tab — column layout
Data starts from row 4. Partners in col E, Dietary options in col G, Allergies in col I. The app reads these to populate dropdowns in the Add Beneficiary form.
4
Beneficiary ref format
Beneficiary refs follow OBA-001 format. The app auto-increments the last numeric ref when adding new beneficiaries. Ensure existing refs are consistent.

⚠ Running Locally: The OAuth Problem & Workaround
Google's Identity Services (GIS) library rejects file:// origins — the sign-in popup will fail silently or show an error. There are two practical workarounds if you want to run the file locally without a web host:
Option A — Use a local dev server
Serve the file over http://localhost instead of file://. Add http://localhost:PORT to your OAuth origins. This is the cleanest solution.
# Python (built-in) python -m http.server 5500 # Node (npx, no install) npx serve . # VS Code: "Live Server" extension Right-click → Open with Live Server
Option B — Store in Google Drive & open via Drive's viewer
Upload the file to Google Drive. Right-click → Open with → Google Chrome (or download and open). Drive itself doesn't host it as a URL — but combined with Option A on a shared machine (e.g. a warehouse laptop), this is a workable team setup.
Shared machine tip: If one laptop is the dedicated "packing station", set up a local server on that machine and bookmark localhost:5500. Store the HTML in a synced Drive folder — updating is as simple as replacing the file in Drive.

Constants Reference config block
SHEET_ID
The unique ID of your Google Sheet, extracted from its URL between /d/ and /edit.
API_KEY
Google Cloud API key restricted to the Sheets API. Used as a fallback read path for public sheets only.
CLIENT_ID
OAuth 2.0 Web Application client ID. Controls which domain can request tokens. Must match the hosted origin exactly.
SCOPES
Two OAuth scopes: spreadsheets (full read/write to sheets) and userinfo.profile (to display the user's name).
Column Index Maps constants
BC (BenColumns)
Maps 21 columns (A–U) of the Beneficiary Database tab. Zero-indexed. Drives all beneficiary data reads and new-row writes.
PC (PickColumns)
Maps 14 columns (A–N) of the Pick Plan tab. Includes STATUS (col H), STATUS_DATE (col M), and ITEM_CODE (col N) for sheet formula joins.
Pick Code Format
Codes follow MMM YY-NNN e.g. MAR25-001. The app appends (N) — the item count — when writing rows, e.g. MAR25-001 (8).
Long-row Format
Each pick produces one sheet row per item. Row 1 of each pick carries meta data (ref, name, date, status); subsequent rows have only item + qty populated.
Security & Scopes
What Access Is Requested
✓ What the App CAN Do
✓ Read all rows from the OBA Operations Google Sheet (any tab by name).
✓ Write new pick rows to Tab 2 (Pick Plan) via append and batchUpdate.
✓ Update status columns (H, M) in Tab 2 for existing picks.
✓ Append new rows to Tab 1 (Beneficiary Database) for new beneficiaries.
✓ Read the user's display name from Google UserInfo (no email stored).
⚠ Scope Notes & Limitations
! The spreadsheets scope grants access to all sheets in Google Drive that the user can access — not just this one. This is a Google API limitation; it cannot be scoped to a single sheet.
! The access token lives in memory only — cleared on sign-out or page close. It is never written to localStorage or cookies.
! Pick status (Prepared/Collected) and amendment notes are stored in localStorage per browser — not synced across devices or to the sheet automatically.
! The API key in the config is exposed in the HTML source. Restrict it to your hosting domain in Google Cloud Console to prevent misuse.
Troubleshooting
Common Issues
🔐
Sign-in popup blocked: Browser popup blockers may block the Google OAuth window. Ensure the sign-in is triggered by a direct user click (not programmatically delayed). Add the hosted URL to browser popup allow-list if needed.
🌐
401 / "origin not allowed": The URL you're accessing from isn't in the OAuth client's Authorised JavaScript Origins. Go to Google Cloud Console → Credentials → edit your OAuth client → add the exact URL (no trailing slash).
📊
No picks loading / blank home: Check the tab names in the spreadsheet exactly match the constants (PICK_TAB, BEN_TAB etc). Tab names are case-sensitive. Open browser DevTools → Console for specific API error messages.
📝
Save fails / 403 error: The signed-in user doesn't have edit access to the sheet. Share the sheet with them as Editor. The API key alone only provides read access to public sheets — write operations require the OAuth token.
